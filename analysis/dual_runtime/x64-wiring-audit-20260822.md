# Blind Soldier x64 wiring audit — 2026-08-22

Scope: source-only review of `fix/condor-probe-silence` at `4d0c8c9`. No files under `C:\Games\Final Fantasy VII` were accessed. This report is the only repository file written during the audit.

Audit targets:

- Midgar Zolom area tracker (`3a43e41`)
- Suspend and resume announcements (`304716d`)
- Spoken opening-movie description and packaged audio asset (`e21e725`)
- Field zone-transition cue (`6320dcd`)
- Honey Bee Inn exit navigation profiles (`4d0c8c9`)

Findings are appended as each source path is traced.

## Finding 1 — Midgar Zolom read failure is spoken like a legitimate inactive Zolom

**Severity: medium; source-supported information loss.** `MidgarZolomStateReader.Read` correctly performs two complete frame reads and rejects a changed frame, so this is not an unguarded torn-read path (`Ff7.Accessibility.LegacyLayout/MidgarZolomStateReader.cs:26-49`). It also returns `IsUsable = false` on a failed header, pointer, record, or coherence check (`MidgarZolomStateReader.cs:52-116,145-158`).

The area tracker then defines presence as `zolom.IsUsable && zolom.State.IsActive` and otherwise returns the generic `"Midgar Zolom marsh."` entry cue (`Ff7.Accessibility.Reloaded/MidgarZolomAreaTracker.cs:64-69`). Consequently, a failed/torn translated-memory read while entering the marsh is indistinguishable in speech from the legitimate state in which the Zolom is inactive. The x64 coordinator does not log the Zolom read diagnostic before passing it to the trackers (`Ff7.Accessibility.Steam2026X64/Runtime/World/Steam2026WorldMapAccessibilityCoordinator.cs:378-419`).

The crossing tracker fails closed and resets on an unusable result (`Ff7.Accessibility.Reloaded/MidgarZolomCrossingTracker.cs:23-39`), which avoids a false run cue but likewise makes a transient read failure indistinguishable from leaving the valid crossing state.

## Finding 2 — Zolom cue speech is not locally exception-guarded

**Severity: low for session stability, but this is an unguarded x64 speech call.** Both the crossing cue and area cue call the x64 `speak` delegate directly, with no `try/catch` in the coordinator (`Steam2026WorldMapAccessibilityCoordinator.cs:396-419`). The trackers update their state before those calls.

The enclosing session does guard the entire world-map observation call: it catches an exception, calls `Suspend`, and logs the failure (`Ff7.Accessibility.Steam2026X64/Runtime/Steam2026ResearchSession.cs:1413-1425`). `Suspend` resets both Zolom trackers (`Steam2026WorldMapAccessibilityCoordinator.cs:346-357`), so a still-true transition can be offered again on the next successful pass. Therefore this call cannot kill the x64 worker/session and is not proven to lose the cue permanently; it can abort one world-map pass and repeatedly fault until the speech sink recovers. It still meets the requested definition of an x64 speech call without a local exception guard.

## Finding 3 — Suspend/resume announcements are genuinely wired and exception-contained

**Status: reachable; no defect found in the normal lifecycle path.** Reloaded enters through `Mod.Start`/`StartEx`, constructs `Steam2026ResearchSession`, and starts its worker (`Ff7.Accessibility.Steam2026X64/Mod.cs:27-38,141-153`). Loader suspend and resume calls directly reach the retained session (`Mod.cs:41-43`); the session changes the worker gate and immediately calls `AnnounceLifecycle` (`Ff7.Accessibility.Steam2026X64/Runtime/Steam2026ResearchSession.cs:109-126`). The worker publishes its output with `Volatile.Write` after constructing Prism/output (`Steam2026ResearchSession.cs:284-318`), and shutdown clears that reference before the scoped output is disposed (`Steam2026ResearchSession.cs:2114-2146`). `AnnounceLifecycle` uses a volatile read and catches every `Speak` exception (`Steam2026ResearchSession.cs:139-162`). Unload disposes and joins the worker through the session before disposing the backend (`Mod.cs:45-57`; `Steam2026ResearchSession.cs:171-188`).

The only skip gates are deliberate `EnableSpeech = false`, or a lifecycle callback arriving before the worker has published output/after teardown; the latter is logged and is not retried (`Steam2026ResearchSession.cs:141-152`). That startup/teardown race can omit the courtesy announcement, but cannot kill the session or create permanent silence during normal play.

## Finding 4 — Both opening-description paths depend completely on the native movie hook cohort

**Status: reachable in a correct package; permanent no-description gate if Reloaded.Hooks cannot be acquired or the hook cohort fatally degrades.** The session always constructs the packaged-track playback output and the shared spoken cue schedule (`Steam2026ResearchSession.cs:284-318`). It attempts to construct and activate all four native movie hooks only when the `IReloadedHooks` controller is non-null, retrying failed construction every setup interval (`Steam2026ResearchSession.cs:880-904`; `Ff7.Accessibility.Steam2026X64/Runtime/Movies/Steam2026NativeMovieHookSet.cs:47-112,117-145`). A recognized opening `Started` event starts the spoken schedule when `EnableOpeningMovieDescription` is true, while the same event is dispatched to the packaged audio-track player when `EnableOpeningMovieAudioTrack` is true (`Steam2026ResearchSession.cs:1500-1560`; `Ff7.Accessibility.Core/RuntimeEventDispatcher.cs:97-128`). The spoken schedule ticks independently of guest-frame readability (`Steam2026ResearchSession.cs:1583-1592`), stops on a terminal movie event/reset/shutdown, and the native hook cohort is disposed at shutdown (`Steam2026ResearchSession.cs:446-470,1521-1543,2114-2146`).

There is no polling fallback on x64. If `Mod` cannot acquire Reloaded.Hooks it explicitly starts the research session with `hooks = null` (`Ff7.Accessibility.Steam2026X64/Mod.cs:100-117,141-153`); the hook-install condition can then never run, no movie event exists, and neither spoken cues nor the OGG track starts. A fatally degraded cohort is likewise disabled permanently for that session (`Steam2026ResearchSession.cs:1573-1579`). This is logged rather than audible. The package declares `reloaded.sharedlib.hooks` as a required dependency (`Ff7.Accessibility.Reloaded/ModConfig.json:13-15`), so it should be reachable in a valid installation, but the source does permit a fully running, otherwise-speaking x64 session with both opening descriptions absent.

The spoken cue's actual x64 `output.Speak` is locally exception-guarded (`Steam2026ResearchSession.cs:303-318`); `OpeningMovieDescription.Start` and `Tick` call only that guarded delegate (`Ff7.Accessibility.Reloaded/OpeningMovieDescription.cs:60-92`). The audio player also catches device/file startup errors and returns false (`Ff7.Accessibility.Reloaded/OpeningMovieAudioTrackPlayer.cs:44-100`). No unguarded speech call was found in this feature.

## Finding 5 — One failed coordinator construction is permanent for three audited features

**Severity: medium; deployment-relevant silent feature loss until game restart.** The session retries translated-reader setup only while `pump is null` (`Ff7.Accessibility.Steam2026X64/Runtime/Steam2026ResearchSession.cs:547-550`). Inside that single setup transaction it constructs field navigation (which owns the Honey Bee profiles), world-map accessibility (which owns both Zolom trackers), and the field zone-transition cue in separate guarded blocks (`Steam2026ResearchSession.cs:603-683`). It then assigns `pump = candidatePump` even when any of those optional coordinator constructors returned null after throwing (`Steam2026ResearchSession.cs:655-691`). Once that happens, `pump` is non-null and the enclosing setup block is never entered again. The affected feature remains absent for the rest of the process.

Each failure is written to the log (`Steam2026ResearchSession.cs:621-640,678-683`), but there is no speech warning and no later retry. This is not the original “compiled but never constructed” bug—the normal path does construct and tick all three—but a one-shot initialization gate can produce the same user-visible result. In particular, the world-map constructor intentionally throws when no map geometry loads (`Ff7.Accessibility.Steam2026X64/Runtime/World/Steam2026WorldMapAccessibilityCoordinator.cs:119-183`); field navigation can throw while loading field/script assets (`Ff7.Accessibility.Steam2026X64/Runtime/Field/Steam2026FieldNavigationCoordinator.cs:83-244`); and the cue coordinator validates its inputs and resolves its player in the same one-time block (`Ff7.Accessibility.Steam2026X64/Runtime/Field/Steam2026FieldZoneTransitionCueCoordinator.cs:35-62`).

This does not make a correctly initialized deployed build worse than the prior build. It does mean a transient or data-readiness failure during startup is not self-healing despite the surrounding setup loop appearing to be a retry loop.

## Finding 6 — Midgar Zolom runtime path is live once the world-map coordinator exists

**Status: genuinely reachable, subject to Findings 1, 2, and 5.** `Mod` starts the session (`Ff7.Accessibility.Steam2026X64/Mod.cs:27-38,141-153`); the worker creates the validated translated address space and the world-map coordinator (`Steam2026ResearchSession.cs:584-588,625-640`); the coordinator constructs both the state reader and area tracker (`Ff7.Accessibility.Steam2026X64/Runtime/World/Steam2026WorldMapAccessibilityCoordinator.cs:18-43,68-92`). Every readable runtime frame reaches the coordinator from the session (`Steam2026ResearchSession.cs:1052-1054,1413-1425`). Its own module gate resets outside world-map module 3, and its foreground/state/runtime gates fail closed (`Steam2026WorldMapAccessibilityCoordinator.cs:191-302`). On a usable foreground world-map frame it calls the combined Zolom path before the world-navigation-enabled gate, so disabling navigation does not disable the area announcements (`Steam2026WorldMapAccessibilityCoordinator.cs:302-315,378-419`). Reset/suspend clear both trackers (`Steam2026WorldMapAccessibilityCoordinator.cs:346-375`), and session teardown disposes the owning coordinator (`Steam2026ResearchSession.cs:2139-2140`; `Steam2026WorldMapAccessibilityCoordinator.cs:422-440`).

## Finding 7 — Field zone-transition cue is fully wired and its translated reads fail closed

**Status: genuinely reachable when explicitly enabled; no per-frame or coherence defect found, subject to Finding 5.** The worker constructs the cue coordinator from the validated shared translated address space in the same setup transaction as the pump (`Ff7.Accessibility.Steam2026X64/Runtime/Steam2026ResearchSession.cs:655-683`). The coordinator always constructs its tracker, and constructs the WAV player only when `EnableFieldZoneTransitionCue` is true (`Ff7.Accessibility.Steam2026X64/Runtime/Field/Steam2026FieldZoneTransitionCueCoordinator.cs:35-62`). Both the code default and shipped configuration are deliberately false (`Ff7.Accessibility.Core/AccessibilityConfig.cs:56`; `Ff7.Accessibility.Reloaded/Configuration/config.json:53`), so silence under an unchanged package is expected rather than a wiring failure.

Every readable worker frame calls `Observe` independently of the field-message feature; foreground/lifecycle state is passed explicitly and the whole call is exception-guarded (`Steam2026ResearchSession.cs:1319-1339`). `Observe` double-reads module and field ID and requires both pairs to agree. A failed or torn read returns without advancing the tracker, so failure is not confused with a real transition (`Steam2026FieldZoneTransitionCueCoordinator.cs:83-101,117-142`). Background transitions intentionally advance the tracker but suppress playback, avoiding a stale cue on refocus (`Steam2026FieldZoneTransitionCueCoordinator.cs:103-114`). Playback catches file/device exceptions and returns false rather than escaping into the x64 session (`Ff7.Accessibility.Reloaded/ImmediateWaveCuePlayer.cs:41-96`). Reset clears the tracker and shutdown disposes all live wave players (`Steam2026FieldZoneTransitionCueCoordinator.cs:144-155`; `Steam2026ResearchSession.cs:461-464,2131-2132`). This feature makes no screen-reader speech call.

## Finding 8 — Honey Bee Inn exit profiles reach the live x64 exit list

**Status: genuinely consumed in normal play; no profile-specific read/coherence defect found, subject to Finding 5.** The x64 project explicitly links the shared catalog (`Ff7.Accessibility.Steam2026X64/Ff7.Accessibility.Steam2026X64.csproj:54`). Session setup constructs the field-navigation coordinator with the translated address space and live output delegate (`Ff7.Accessibility.Steam2026X64/Runtime/Steam2026ResearchSession.cs:603-623`), and every readable worker frame calls its `Observe` under an outer exception guard (`Steam2026ResearchSession.cs:1427-1464`). The coordinator is active only while the field module owns a foreground game and at least one relevant navigation/cue feature is enabled (`Ff7.Accessibility.Steam2026X64/Runtime/Field/Steam2026FieldNavigationCoordinator.cs:272-323,830-851`). The shipped configuration enables both field navigation and exit proximity (`Ff7.Accessibility.Reloaded/Configuration/config.json:57,98`).

The live target path is complete: it combines native gateways with currently enabled script exits, applies `FieldExitNavigationProfileCatalog.Apply` to that combined list, then labels and filters it for presentation (`Steam2026FieldNavigationCoordinator.cs:1513-1542,1577-1579`). The catalog widens the four field-218 Honey Bee door radii and adds the upper-Wall-Market detour while leaving all other targets unchanged (`Ff7.Accessibility.Reloaded/FieldExitNavigationProfileCatalog.cs:5-48`). Those profiled targets feed `currentExits`, then the route planner and `ReachableFieldExitTargetProvider`, and finally both exit proximity and the navigation controller (`Steam2026FieldNavigationCoordinator.cs:145-205,476-502`). This is not merely a compiled type: it is called on every successful exit refresh.

The exit refresh treats translated state as a transaction rather than a collection of unrelated plain reads: it obtains a checked gateway snapshot, verifies field/model ownership, brackets target construction with the game-moment value, re-reads field/model ownership, and publishes only a stable candidate set (`Steam2026FieldNavigationCoordinator.cs:1422-1510`). Failed reads produce an unavailable result and clear/withhold exits instead of being accepted as a legitimate empty snapshot. Reset, suspend, and dispose clear the publication/spatial state and dispose its players (`Steam2026FieldNavigationCoordinator.cs:863-918,929-956`; `Steam2026ResearchSession.cs:2135-2136`).

The profile itself introduces no speech call, but guidance produced from it reaches the coordinator's `Speak` helper, whose direct delegate invocation is not locally guarded (`Steam2026FieldNavigationCoordinator.cs:1623-1633`). The enclosing session catches the exception, resets navigation, logs it, and continues (`Steam2026ResearchSession.cs:1427-1464`). Thus a throwing x64 speech backend can discard that one navigation utterance and reset the route state, but it does not terminate the worker.

## Finding 9 — Opening audio-description asset is declared and package-gated for both runtimes

**Status: confirmed from both project declarations and the dual-runtime package script.** The x86 project declares `Assets\movies\opening_audio_description.ogg` with `CopyToOutputDirectory=PreserveNewest` (`Ff7.Accessibility.Reloaded/Ff7.Accessibility.Reloaded.csproj:43`). The x64 project links that same source asset at the same output-relative path and also marks it `PreserveNewest` (`Ff7.Accessibility.Steam2026X64/Ff7.Accessibility.Steam2026X64.csproj:65-76`). Therefore an individual publish of either project contains the asset in its runtime tree.

The dual-runtime package additionally publishes x86 and x64 into separate staging directories, then copies the entire shared `Assets` tree to the package root (`Build-DualRuntimePackage.ps1:499-513`). Package validation explicitly requires `Assets\movies\opening_audio_description.ogg`; a package without it cannot pass that script (`Build-DualRuntimePackage.ps1:380-395`). Both runtime hosts resolve the configured relative track against their common mod root (`Ff7.Accessibility.Reloaded/Mod.cs:8505-8512`; `Ff7.Accessibility.Steam2026X64/Mod.cs:239-246`), and the shipped path is exactly `Assets\movies\opening_audio_description.ogg` (`Ff7.Accessibility.Reloaded/Configuration/config.json:15`). The source supports a definite yes: the built dual-runtime package contains the OGG at the path used by both hosts.

## Finding 10 — The shipped opening description is the OGG path; timed Prism cues remain opt-in

**Status: configuration clarification, not an x64 wiring defect.** `EnableOpeningMovieAudioTrack` defaults to true and the shipped config leaves it true, while `EnableOpeningMovieDescription` (the seventeen timed screen-reader lines) defaults to false and is shipped false (`Ff7.Accessibility.Core/AccessibilityConfig.cs:15-19`; `Ff7.Accessibility.Reloaded/Configuration/config.json:12-16`). The x64 code reads both gates (`Ff7.Accessibility.Steam2026X64/Runtime/Steam2026ResearchSession.cs:1526,1589`; `Ff7.Accessibility.Core/RuntimeEventDispatcher.cs:109-123`). Therefore a stock install should play the packaged OGG and should not additionally speak the timed Prism schedule. Turning the spoken-description key on now has a live consumer; leaving it unchanged does not exercise that new path.

## Finding 11 — Zolom and player snapshots are individually stable but not one atomic observation

**Severity: low; narrow cross-frame race, not a plain torn page-table read.** The world-map coordinator first accepts the pump/state reader's player snapshot, then performs a separate double-snapshot of the Zolom and combines the two to evaluate shoreline distance, terrain, and presence (`Ff7.Accessibility.Steam2026X64/Runtime/World/Steam2026WorldMapAccessibilityCoordinator.cs:263-302,378-409`). `MidgarZolomStateReader` validates module/map type and requires two identical complete reads (`Ff7.Accessibility.LegacyLayout/MidgarZolomStateReader.cs:26-49,52-116`), so neither half is an unguarded multi-value translated read. There is, however, no final re-read bracketing the already-captured player snapshot. The game can advance between those two independently stable observations, allowing a boundary case to use a player position from one frame and a Zolom position/presence from the next. The source supports at most a one-observation timing skew, not arbitrary torn coordinates; it is most relevant to the crossing-window cue near its threshold.

## Finding 12 — Suspend/resume's cross-thread speech handoff is serialized at the native backend

**Status: no cross-thread speech race found.** Loader lifecycle callbacks can call `Steam2026ResearchAccessibilityOutput.Speak` concurrently with the worker, but all native backend selection/output/free operations are serialized by `PrismNativeSpeaker.backendSync` (`Ff7.Accessibility.Reloaded/PrismNativeSpeaker.cs:13-16,148-175,199-215`). The repeat-last state updated after successful output has its own lock (`Ff7.Accessibility.Reloaded/RepeatLastSpeechController.cs:11-24,39-49`). Combined with the volatile publish/clear and local exception guard already described in Finding 3, the new lifecycle announcement does not expose an unprotected Prism call or a use-after-dispose path.

## Audit conclusion

No audited feature is merely compiled and abandoned. All five have a real x64 construction and runtime-consumption path, and all five have reset/stop/disposal handling. No source-supported session-killing speech escape was found: the two direct, locally unguarded delegates (Zolom and field navigation) are caught by their session-level observation guards.

This is **not a clean general-release sign-off** because Findings 1 and 5 are medium risks: an unusable Zolom read is rendered as the less-informative legitimate entry cue, and an optional coordinator that fails construction once is never retried or announced. Finding 11 adds a narrower one-observation Zolom/player skew. None of those proves that Brice's test deployment will crash or lose existing Fort Condor behavior, and no packaging defect was found. They do mean the five ports should not be described as fully fail-closed until those paths are addressed.

Per-feature result:

- Midgar Zolom: live; read-failure semantics and cross-snapshot timing need correction.
- Suspend/resume: live and exception/thread safe.
- Opening movie: live when the required native hook cohort is available; OGG is the default description, timed Prism cues are opt-in.
- Zone-transition cue: live, coherent, exception-contained, and deliberately off by default.
- Honey Bee exits: live in the actual exit-refresh/route path; translated target publication is coherence-guarded.
